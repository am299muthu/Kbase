# MCP integration

Implementation: [`kb/mcp_server.py`](../kb/mcp_server.py). This directory is documentation only (not a Python package named `mcp`, which would shadow the official SDK).

The host uses the official `mcp` Python SDK, starts a private subprocess over **stdio**, sends `initialize`, discovers tools using `list_tools`, and invokes them via `ClientSession.call_tool`. `kb/agent.py` consumes the actual returned evidence; no canned tool results or direct-function replacement is used. Each chat session gets an isolated MCP process. This is simple but incurs process startup latency; pool identity-isolated sessions for production.

| Tool | Input schema | Output / effect |
|---|---|---|
| `lookupemployeeaccesscontrol` | `{}` | Current employee ID, own folders/roles and PII visibility |
| `listbusinessfolders` | `{}` | Only visible folder IDs/paths and predefined business metadata |
| `searchdocuments` | `{query: string, top_k?: integer}` | Current-entitlement-filtered evidence, stable chunk IDs, source lineage and masking mode |
| `getdocsection` | `{chunk_id: string}` | One section, subject to fresh entitlement/status/retention checks |
| `checkpiicompliance` | `{text: string}` | Masked output according to current employee flag, plus detector mode; not a compliance certification |
| `requestaccess` | `{folder_id: string, reason: string}` | Audited review request only, **never** a permission grant |

Actual JSON schemas are generated by FastMCP from function annotations and returned during discovery. Query/text/reason limits and retrieval-k clamps are enforced server-side. The host sets `KB_MCP_SESSION` to a short-lived opaque database session token in subprocess environment. Identity is **not** a model-controlled tool argument. Never expose this stdio server as an unauthenticated HTTP service, publish environment variables, or log the token. Session expiry/revocation and employee activation are checked on each tool call. Final egress rechecks every traced evidence ID and current folder set to avoid returning stale evidence after access revocation.

## Workflows

1. Policy question: access lookup → folder metadata → search → resolve retrieved sections (multiple sources when retrieved) → optional OpenRouter evidence synthesis → PII gateway. Returned trace includes tool names, actual arguments/results, durations and citations, not hidden chain-of-thought.
2. Access explanation: access lookup → folder metadata → PII gateway. An explicit `Request access to technology` message creates a pending owner review request and never changes access. No policy answer is invented from this structured data.

The policy orchestrator is intentionally a bounded **code-planned** workflow, not an unconstrained LLM tool-selection loop. Full open-ended model planning, independent compliance approvals and actual ticket fulfilment are future work. A review request is not an approved workflow completion.

## Live smoke command

```sh
.venv/bin/python -m kb.cli init --demo-documents
.venv/bin/python -m kb.cli mcp-check
```

This discovers all six tools and executes an authenticated employee lookup through stdio, then removes its temporary session. CI performs the same check.
